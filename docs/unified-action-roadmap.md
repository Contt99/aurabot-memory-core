# 统一行动入口：实施与验收

基线为当前 Aurabot 1.2.1 和已部署的外置模块。暂不升级、不关闭现有手工入口、不新增宿主补丁。利用宿主的模块目录和正式调用钩子接管；模块未纳管的直接执行不冒称完整覆盖。

1. 先打通 B 站样板和动态工具：`life-core` 从宿主取当前运行模块，读取其显式只读能力；新能力要有后台授权，安装不是授权。将原 `bili_browse` 和自主生活的 `bili` 兼容动作改用只读路径；聊天看链接、人工/已授权 B 站互动不换权限。验证装一个合成新工具即可发现，撤权/停用立即不可用，B 站探索不触发评论、点赞、弹幕、QQ 分享，调用有结果记录。
2. 建立统一后台派发：模块声明任务和到期计算，核心一次调度、保留来源配额和重启防重，随后按 B 站→贴吧/RSS→主动搭话→日记迁移。只在新链路验收后停掉同一个旧定时器。睡眠状态维护、存档和普通聊天不进入探索额度。
3. 用覆盖数据驱动面板：逐入口区分已接入、只观察、未纳管；从任务/结果查来源、QQ 回执和模型请求。不把受理、一次轮询或独立管理员操作算成她做过的事。
4. 继续收紧上下文顺序及事实证据：明确 QQ 引用 → 紧邻对话 → 相关旧经验。保留完整原文、精选事实、分聊天读取、两套独立日记群名单和精确取消/忘记。
5. 验收按现有宿主分阶段进行。合成测试不得对外实际发帖、评论或写入 QQ；先验代码、不重置状态，空闲安装用户模块。回滚代码不覆盖新数据。

## 首批候选

`life-core 0.2.0-local.6`、`autonomy 0.7.0-life.6`、`bili 1.1.0-life.4`、`rss-reader 1.0.0-life.3`。动态能力发现复用当前宿主的运行模块清单；B 站只读与互动分开；统一时钟已可派发这三个模块的原到期检查。原手工入口、时间窗、配额与平台授权沿用。到期检查不会伪装成经历，平台实际执行的回执仍走既有账本。

下一批先补有身份的后台候选及实际结果关联，再迁移贴吧、主动搭话和两种日记；同时补齐引用与紧邻对话的优先级。禁止在没有回执的情况下回填成功；持久队列不能重放外部写入。切换线上前确认旧定时器没有在跑、模块加载成功、统一时钟接管且原手工入口可用。

## 上下文衔接检查点

`life-core 0.2.0-local.7` + `history-vault 0.1.7-local.life.1`。普通追问先放入同会话紧邻的话；旧 GIF 描述只有问题指向图片或本轮确有图时才参与取材。精确引用依赖当轮真实 QQ 入站身份，已支持 1.2.1 提供的群聊直接请求者和私聊原生附件。1.2.1 的纯文本私聊提示钩子没有当前 QQ 消息 ID：保留宿主已带入的引用，不按最近行、相似文本或时间倒推身份。

## 贴吧自动分享：后台候选及回执

- 平台通过已注册的作业 ID 和稳定原生素材／到期身份提交候选；持久队列只存可重新验证的来源、范围、出口、时间和参数，不持久化任意执行闭包或凭据。重复提交不占主动尝试额度。
- 核心先按提醒或主动联系的既有策略裁决，再领取候选执行。未通过睡眠、时段、权限或额度时保留原资格语义；实际尝试才占原额度。普通 QQ 回复和手工入口继续独立，既有模块授权不得随迁移扩大。
- 真正收到 QQ 回执才记已发送。成功、确定未发送、结果未知分开，进程中断时不重放已领取的外写。需要等待异步回执的任务保留关联键，旧版没给出回执的入口在面板显示未覆盖。
- `life-core 0.2.0-local.8`、`tieba-reader 1.5.2-life.6` 接通：楼主可读正文 → 候选 → 复核 → QQ 回执 → 下一轮原话。有效期最多到下一次浏览或北京时间日界；睡眠、共享静默和主动间隔可使候选顺延，未获资格不预扣。手工分享仍走原入口，成功回执与旧手工记录合计计算贴吧单独日上限。
- 候选不存草稿和正文，模型实际使用的正文从账本读取。忘记会清除候选关联并阻止未发送的草稿；保留只用于防复活的帖子编号组合及历史状态、回执。已经送达的 QQ 原文保留，派生记忆不再自动取用。WebUI → 行动与记忆 → 任务与健康 → 后台行动回执，可查状态和关联经历。
- 其余主动行为继续保留原入口。不要把已接管的到期检查当成已统一的外部送达。
- 部署或回滚时配套替换以上两个模块的源码文件，保留线上贴吧已有的 `lib/browser.cjs`、浏览器运行时与会话。新贴吧找不到候选接口会暂停自动浏览，不退回直接发送；手工入口不受此版本组合限制。

## 两套日记的调度与回执

- `life-core 0.2.0-local.9`、`diary 1.0.0-life.4`、`autonomy 0.7.0-life.7`。公开日记由原随机日计划提交每日候选，窗口结束即失效，不另消耗 QQ 私聊额度；已有确认回执计入当天一篇上限，独立的手工发说说工具与日记预览保持原入口。
- 私人日记仍须由自主生活当轮选中，不加定时器或每日配额；沿用活跃时段和模型授权。只有通过原核验并原子保存到服务器才显示「已保存到服务器」，不接触空间接口，不把私人正文注入其他聊天。两套来源白名单保持独立。
- 核心在实际写入前复核权限并落盘写入状态。空间以 SnowLuma 返回的说说编号和时间确认，本地以文件中的日记 ID 确认。空间候选关闭网关重试；结果不明时自动不重发，「立即写日记」也会提醒先查看 QQ 空间。独立手工发说说工具仍可使用。候选记录仅留状态、回执和来源引用，不保存草稿；私人日记被忘记后清掉对应本地正文和回执引用。
- 下一批：保留目的引擎与旧主动搭话之间的互斥、白名单朋友和桌宠回落语义，迁移主动搭话的候选及实发回执；继续标清 B 站、RSS 等仍未纳管的直接出口。

## 目的引擎的定时搭话与追问

- `life-core 0.2.0-local.10`、`purpose 1.0.0-life.6`。目的引擎声明日常搭话、追问两种候选，原定时入口由核心时钟接管。排队本身不扣额度；只有实际领取尝试才占用原共享额度。追问用当前仍有效的原生消息编号定位她上一句有回执的问题；原短窗口与共享空闲没有交集时不制造无效候选。
- 每个候选只处理一个私聊目标。选中后用专属记忆快照生成短文字，QQ 出口使用宿主 `sendText` 的 `isCurrent`，在异步发送过滤结束后、交给 OneBot 前复核权限、源与新消息。只用本次调用返回的原生编号确认送达；按实际发出的文字补流水与心情事件。普通聊天与手动目的引擎的分条、语音、表情链路保持不变；新版定时目的引擎的 QQ 路径不执行任意富媒体动作。
- 桌宠优先／回落配置保留。若桌宠内部投递，仍走该模块自己的接口，不以气泡返回值冒称 QQ 送达；外置桌宠自身回落的最后一跳和气泡接收回执尚未验证。已交给 OneBot 的调用无法撤回，结果未知不自动重发。
- 平台直发、桌宠本机送达、异步任务完成仍分别盘点。

## 旧主动搭话、自主搭话与运行覆盖

- `life-core 0.2.0-local.11`、`speakup 1.0.0-life.3`、`autonomy 0.7.0-life.8`。旧主动搭话定时轮与目的引擎互斥。旧定时轮改用同一核心做私聊候选、短文本生成和原生回执；不再向对方的现有对话塞一条系统发言或暗中授予该会话工具权限。面板手工入口保持原来的会话投递。朋友目标仍须获两层私聊授权，且不可引用主人或第三者私聊。
- 自主生活实际决定想搭话时只提交一个主人私聊候选，进入同一 QQ 额度和原生发送链。候选记录关联当轮；未收到网关回执前，活动只显示「已排队」。关闭自主生活或撤销模型授权后，等待中的自主搭话不执行。
- WebUI「任务与健康」按宿主实际加载的模块接口列出已接管、只接管到期检查、只观察、仍走原入口和未加载，另显示当前配置能证明的时段冲突。频率是到期检查，不是预计发送。例：共享空闲 40 分钟与原追问上限 40 分钟没有交集；保留原设置，不为追问绕过共享规则。
- 剩余的 B 站、RSS、桌宠和异步任务实际完成回执逐项验收；不能用「核心时钟接管」代替「所有结果已接管」。

## QQ 空间定时互动

- `life-core 0.2.0-local.13`、`qzone-social 1.0.0-life.5`。核心时钟接管到期检查；模块仍负责逛动态、挑选对象、判断概率和撰写。动态的 `key` 只用于去重，实际操作必须有平台返回的说说 `tid`；一级评论与同号二级评论分别跟踪。核心复核账号、开关、时段、配额、来源和草稿后才调用 OneBot。
- 定时评论与回复用 SnowLuma 的新评论编号确认，点赞接受其成功信封中的 `data:null`。明确拒绝不占额度；回执不明不重发，未确认评论保留当日一个空间名额但不计入已发数量。空间额度与 QQ 私聊主动额度独立。
- 定时互动的观察和原文只供主人范围查询，面板从同一账本读取近期成功结果。不再把定时空间正文复写进全局记忆；忘记会撤下本地派生视图，不替用户删除 QQ 空间已发布内容。手工入口保留；在自己说说下仍沿用带「回复 某人」前缀的顶层评论，不改成楼中楼通知。
- 自动互动要求核心提供空间接口，接口缺失时暂停，不回退到直写。热加载模块前后保留账本和现有配置；如果回滚到历史旧版，先停自动互动、核对未确认记录，避免旧路径重复发布。

## 夜间行动与自然醒后问候

- `life-core 0.2.0-local.14`、`night 1.0.3-local.sleep.2`。精力、睡眠与醒来是独立状态时钟，不因暂停核心停摆。自动梦境的检查由核心执行，沿用 REM、间隔和次数设置。睡眠周期和尝试序号稳定标识一次执行；先登记尝试，成功原子写入梦文件才记保存回执。模糊或失败不显示已保存，梦境正文不进入经历上下文。
- 只为绑定当前主人的自然醒事件提交问候；从真实起床点起 5 分钟内有效。私聊的时段、静音、空闲、冷却和额度统一处理；不满足就过期，不擅自改作息或补发。原生 QQ 消息编号确认实发，主人变更、再次入睡或关掉设置使未发草稿失效。
- 睡前道别仍属于当前正常聊天回复，不占后台额度。手工睡醒、管理梦境和主人私聊查梦保留。WebUI 的「入口覆盖与时段」区分自动梦境与主动问候；只有时区可比且整段夜间起床窗口没有交集时才报确定冲突。

## B 站定时点赞、评论和回评

- `life-core 0.2.0-local.15`、`bili 1.1.0-life.5`。B 站模块仍决定刷什么、选哪个视频和是否互动；核心使用实际视频/站内回复通知，以及当前登录账号和范围，核对稳定目标后才让平台客户端发起写入。回评的父评论与回复对象来自通知，不由模型指定。
- 写前再次检查登录凭证是否变更、开关、原额度、草稿和来源；在 HTTP 请求前持久标记「发送中」。点赞以 B 站成功响应为准；评论和回评以还原无损的原生评论编号确认。网络错误、不完整回执或重启不自动重发。明确拒绝不占不确定名额；回执不明保留当日名额但不计为已发。B 站评论与回评仍分别计数，不占 QQ 主动额度。
- `watch` 读取结果区分视频资料、字幕、评论和抽帧线索，站内回复通知与派生回评不写进共享流水。手工入口不变。旧核心不支持新平台队列时，定时浏览可读取，但不回退到评论或点赞直发。
- 自动弹幕仍使用模块自己的提交记录，暂不标为由统一队列处理。

## B 站分享和截图到 QQ

- `life-core 0.2.0-local.16`、`bili 1.1.0-life.6`。B 站浏览轮继续选视频、写分享短句、按原概率选择截图；核心保存最多 8 分钟有效的候选，不再向模型询问一遍。分享和截图只给主人，分别通过共享的私聊时段、静音、空闲和额度。主人开始聊天、来源撤销、截图被删除、总开关或对应设置关闭，未发出的动作停止。
- 草稿与候选一同落盘，发送完成、失败、不确定、过期或忘记后清理。截图只使用实际抽取且仍在截图库的 JPEG；带说明时是一条 QQ 消息，不再先发图再发第二次无回执说明。原生 QQ 编号须与观察到的链接或图片匹配，确认过的原话进入同一私聊的后续上下文。超时或内容被过滤改掉不自动重发。
- 手工分享和截图工具保留。自动路径缺新核心时不回退到直接发 QQ。回滚到旧版前先暂停自动浏览、核对待处理和未知回执，并保留持久账本。

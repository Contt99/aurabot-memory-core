# 跨会话历史库（history-vault）

授权 QQ 聊天的完整原文永久留在本机 SQLite；日摘要、月印象继续按已有节奏整理。聊天会话重开或摘要压缩不会删除 L0 原文。显式“忘记”和管理面板“清空”除外。

## 三层数据分别做什么

| 层 | 内容 | 保存与读取 |
|---|---|---|
| L0 `vault_lines` | 完整文字、原始 QQ 消息段/事件 JSON、真实消息 ID、来源时间；ASR 等衍生文本单独关联 | 不按每日行数、单条长度、日期自动裁剪或删除 |
| L1 `vault_days` | 每聊天每日摘要，最多 300 字 | 模型只读有界视图；保留既有整理、幂等和调用预算规则 |
| L2 `vault_months` | 每聊天每月印象，最多 200 字 | 由日摘要生成，不取代原文 |

数据库位于 `api.dataDir()/vault.sqlite`。文字保留原有空格、换行和相邻文字段顺序；`rawJson` 保存原始入站事件或最终出站消息段，`derivedJson` 保存与真实消息 ID 关联的处理后文本。媒体仅保留实际收到/发出的 QQ 段、URL、标识及本来就在段中的内容，不额外下载附件；外部媒体 URL 仍可能过期。

## 原文从真实消息入口归档

- **入站 `onebot`**：宿主在命令、静音、不回复、其他模块接管之前转发原始消息。模块同时检查机器人账号、Aurabot 主人/私聊/群白名单及本模块记录名单；未授权聊天、自身消息和 `message_sent` 不纳入入站归档。总开关或归档开关关闭时不继续记录。
- **出站 `sent`**：只记录网关确认成功的最终消息段，包括命令回复和文件上传；预检 `send`、模拟、试运行、失败尝试不算已发送。`at` 是操作开始的高精度 epoch 时间，不是迟到 ACK 的时间。
- **关联与防重**：以实际 `chatId + 方向 + QQ消息ID` 防重。`activity.messageId` 只关联 ASR 等衍生内容，不把同条消息再插入一次；只有旧的仅 activity 集成保留兼容入口。不用文本相似度猜测两条消息是否相同。

独立的非消息通知（例如只有 `group_upload` notice 而没有 message 的群文件上传）不冒充消息原文；本入口不扩展成通知/附件永久采集器。

原始 QQ 时间通常只有秒级。实时事件以高精度收件顺序处理，忘记后同一秒的新消息不会被当成旧消息。已忘消息的真实 ID 持久保存在墓碑中，已知旧事件重放不会复活。若旧数据从未提供稳定 ID，仅靠秒级时间和相同文字无法可靠区分重放与新消息；不做猜测合并。

## 模型读取有界，存储不裁剪

- 日摘要最多读取最近 400 条的文字视图，每条最多 600 字符，总视图不超过 24,000 字符。输入明确标注其为部分视图，不冒充全天逐字全文。
- `recall_history` 的原文回执也有每条/总长度上限；关键词命中会定位到长消息中的命中附近，并标出行内截取位置。可按日期或关键词继续查询。
- 自动备忘最多 14 天、4,000 字符；常规默认仍为 3 天、700 字符。
- 管理 `/read`、`/dump` 返回所选记录的完整文字，保留原有记录条数分页上限；消息段 JSON 可在本地数据库读取。管理面板展示的是最近片段，不是整库一次全部加载。

模块不抓网页或附件；数据库落本机。摘要和工具的有界视图会交给宿主配置的模型。

## 开关与配置

| 配置 | 默认 | 当前含义 |
|---|---|---|
| `enabled` | 开 | 关闭后不归档、不注入备忘 |
| `recordGroups` | 开 | 是否记录授权群的原始消息，不影响私聊 |
| `groupList` / `privateList` | 空 | 在 Aurabot 实际授权白名单内再筛选；空不扩大实际授权范围 |
| `keepDays` | 0 | 兼容旧键，但不再控制 L0 清理；旧的正数也不会自动删除原文，界面已移除这一误导选项 |
| `compressAfterDays` | 1 | 已结束的日子何时整理日摘要，不删除原文 |
| `monthAfterDays` | 32 | 何时整理月印象，不删除原文 |
| `dailyCalls` | 24 | 每天压缩调用预算，模块重载不重置 |
| `injectDays` | 3 | 自动备忘天数，硬上限 14 |

`/史库 关键词` 和 `recall_history` 只查当前聊天：群里主人的命令也不能读取别群/私聊；本人私聊不能读取别人的私聊。管理面板保留受管理边界保护的全库读取。

## 显式忘记与旧数据

自然语言忘记请求通过主记忆确认后同步清理本人匹配的原文、关联 ASR 和受影响摘要；请求本身不再作为历史事实留存，包括对应的语音请求原文。墓碑阻止已忘 QQ 消息 ID 重放，在途压缩或迟到发送确认也不能写回旧内容。独立 DSH 会话与系统备份不在这一清理操作内。管理按 ID 删除主记忆仍不等同于清空历史库。

升级只增加存储字段，保留旧行；旧行缺少原始消息 JSON 或 QQ 消息 ID 就保持为空，不伪造恢复。此前没有收到、已经截断或已删除的内容，不能凭新代码凭空补齐。恢复评估见交付目录的 `RETENTION-RECOVERY.md`。

## 0.1.3-local.3：印象卡片接收对象补充

新增内部只读导出 impressionRecipients({userId,scope,since,limit})，最多500条本人入站消息。group:群号仅本群；self仅本人各群发言与本人私聊；public仅本人群发言。返回本人文字、原始消息ID、@QQ和同聊天回复作者QQ，不返回被引用正文或rawJson。不调用模型、不新增数据库字段、不增加HTTP路由。旧行无元数据就保持未知；显式忘记/清空删除后的事件不再返回。原文归档、压缩与保留策略不变。


## 统一经历的只读日记素材（0.1.4-local.life）

`diaryMaterial({groups, since=0, limit=60})` 只读取显式指定、且仍在宿主 `allow.groups` 内的群。空名单不读取任何群；只返回入站行，最多 100 条。素材保留真实发送者、原生 @、同聊天内可验证的回复作者；未知作者保持空字符串，不带被回复正文、转发正文或原始 JSON。`id` 为稳定的 `vault:<rowId>`。

`diaryMaterialCurrent(ids)` 检查这些确切行是否仍存在并仍获宿主群授权，不会因无关新消息或时间窗口移动而拒绝旧素材。日记自己的公开/私密来源群名单由消费者另行检查。原有 `forgetPerson`、墓碑防重放和在途压缩失效规则继续生效。


### 精确来源忘记联动（0.1.5-local.life）

`forgetPerson` 与面板 `/forget` 在实际删除事务提交后，将已删除的 `vault:<rowId>` 交给 `life-core.forgetPerson('', '', {exactSources:true,sourceIds})`，使仅依赖这些来源的笔记/私人日记同步失效。这里不再次按人或正文关键词扩散，不触碰其他人同词记录，也不让核心递归删除历史库。没有实际被删来源时不调用核心。核心缺失、失败或返回异步结果时，历史库本地删除仍然有效，返回 `lifeCoreForgetErrors`、明确的未完成 message，并记录 error；原 host 的历史库联动照常继续。


## 0.1.6-local.life：统一核心只读来源出口

- `timelinePage({afterId=0,limit=200,chatId='',beforeAt=0})` 按永久行号递增读取，最多500条；返回 `{rows,nextId,hasMore}`。跨过当前撤权的行仍推进游标，不把后面的获准记录截掉。
- `timelineRecent({chatId,limit=12,beforeAt=0})` 只读明确当前聊天，最多50条，按时间正序返回；未来时间不作为当前近况。
- `timelineCurrent(ids,{chatId})` 重验具体原文是否仍在，以及当前宿主与归档名单是否仍允许。未知原时间为 `t:0`，`observedAt` 单独保留真实接收时间；不以回填时间代替发生时间。
- 原文、QQ身份、真实@及同聊天回复对象不截断、不猜配；不导出原始JSON到核心提示材料。`contextManaged('chat')` 接管后不叠加旧日摘要备忘；缺少新核心仍保留原入口，但撤权摘要不能经旧工具读出。
- 显式忘记和清空按聊天将已删 `vault:<id>` 与真实QQ canonical身份一起同步失效。原文存储合同不变。

## 0.1.7-local.life：印象卡原话依据

`impressionMaterial({userId,scope,since,limit})` 在当前归档与宿主权限内读取目标QQ本人的入站话语，包括不带 @ 或回复的普通消息；撤权行不会挤占获准话语的数量。群卡只读本群，`self` 另可读本人私聊，`public` 不读私聊。管理面板的测试注入、没有可归属入站事件的旧行、其他人的消息都不是卡片原话。

`impressionMaterialByIds(ids,{userId,scope})` 用稳定行号重验相同来源权限并读取当前仍存的片段。回复作者只从同聊天可确认的原消息取得，其行号也随接收对象线索登记；不返回被回复的正文。索引仅加速按发言人和时间查询，不改原文、忘记或归档策略。旧 `impressionRecipients` 入口保留。
